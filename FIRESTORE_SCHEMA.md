# Firestore Collections — Schema Reference

> Project: **Dress Shop**  
> Region: `asia-south1`  
> Rules file: `firestore.rules`  
> Indexes file: `firestore.indexes.json`

---

## Collections Overview

| Collection | Created by | Purpose |
|---|---|---|
| `products` | Admin (Cloud Function / direct SDK) | Product catalogue |
| `orders` | Any user / guest (Cloud Function / direct SDK) | Purchase orders |
| `payments` | Cloud Function (`apiVerifyPayment` / `apiRecordPayment`) | Payment transaction ledger — **never stores card/CVV data** |
| `users` | Cloud Function on profile update | Extended user profiles |

---

## 1. `products/{productId}`

**Document ID:** Auto-generated by Firestore (`addDoc`) or provided explicitly.

| Field | Type | Required | Notes |
|---|---|---|---|
| `title` | `string` | ✅ | Product name |
| `description` | `string` | | Defaults to `""` |
| `price` | `number` | ✅ | In INR (Indian Rupees) |
| `category` | `"men" \| "women"` | | Defaults to `"women"` |
| `images` | `string[]` | | Array of image URLs or base64 data-URLs |
| `sizes` | `string[]` | | e.g. `["XS","S","M","L","XL","XXL"]` |
| `image` | `string` | | Convenience field — always equals `images[0]` |
| `createdAt` | `Timestamp` | ✅ | Set by server on `addProduct` |
| `updatedAt` | `Timestamp` | | Set by server on `updateProduct` |

**Example document:**
```json
{
  "title": "Red Floral Dress",
  "description": "Elegant red dress for special occasions",
  "price": 1999,
  "category": "women",
  "images": ["https://example.com/red-dress.jpg"],
  "sizes": ["S", "M", "L"],
  "image": "https://example.com/red-dress.jpg",
  "createdAt": "2026-03-21T10:00:00Z"
}
```

**Security rules:**
- `read` — anyone (public, no auth needed)
- `write` — only users with `isAdmin: true` custom claim

**Composite index:**
- `category ASC + createdAt DESC` — used for category-filtered product listings

## 2. `orders/{orderId}`

**Document ID:** Client-generated (`generateOrderId()`) or auto-generated by Firestore.  
Format when client-generated: `ORD-<timestamp>-<random>` (see `generateOrderId.ts`).

| Field | Type | Required | Notes |
|---|---|---|---|
| `id` | `string` | | Client-supplied order ID (mirrors the doc ID) |
| `userId` | `string` | ✅ | Firebase Auth UID for logged-in users; `guest_<timestamp>` for guests |
| `userEmail` | `string \| null` | | From token or `contactEmail` in body |
| `isGuest` | `boolean` | ✅ | `true` when no Firebase token was present at order time |
| `contactEmail` | `string` | | Email entered in checkout form |
| `status` | `OrderStatus` | ✅ | See status enum below |
| `items` | `CartItem[]` | ✅ | Array of cart items (see sub-schema below) |
| `total` | `number` | ✅ | Order total in INR |
| `shippingAddress` | `AddressData` | ✅ | See sub-schema below |
| `billingAddress` | `AddressData` | ✅ | Same as shipping when `billingOption === "same"` |
| `billingAndShippingAddressSame` | `boolean` | | `true` when both addresses are identical |
| `paymentId` | `string` | | Razorpay payment ID — set after payment verification |
| `razorpayOrderId` | `string \| null` | | Razorpay order ID from `apiCreateRazorpayOrder` |
| `paidAt` | `Timestamp` | | Set by `apiVerifyPayment` when payment is confirmed |
| `guestId` | `string` | | Optional stable guest identifier sent by client |
| `createdAt` | `Timestamp` | ✅ | Set by server on order creation |
| `updatedAt` | `Timestamp` | | Set by server on status update |

### `status` enum

```
pending → confirmed → processing → shipped → delivered
                                           ↘ cancelled
```

| Value | Meaning |
|---|---|
| `pending` | Order created, payment not yet verified |
| `confirmed` | Payment verified by Razorpay HMAC check |
| `processing` | Admin has started processing |
| `shipped` | Dispatched |
| `delivered` | Delivered to customer |
| `cancelled` | Cancelled by admin |

### `items[]` — CartItem sub-schema

| Field | Type | Notes |
|---|---|---|
| `productId` | `string` | Firestore product doc ID |
| `title` | `string` | Product title at time of order |
| `price` | `number` | Unit price in INR at time of order |
| `qty` | `number` | Quantity ordered |

### `shippingAddress` / `billingAddress` — AddressData sub-schema

| Field | Type | Notes |
|---|---|---|
| `firstName` | `string` | |
| `lastName` | `string` | |
| `company` | `string` | Optional, can be empty |
| `address` | `string` | Street address |
| `apartment` | `string` | Apartment / suite, can be empty |
| `city` | `string` | |
| `state` | `string` | Indian state name |
| `pinCode` | `string` | 6-digit Indian PIN code |
| `phone` | `string` | 10-digit mobile number |

**Example document:**
```json
{
  "id": "ORD-1711011234567-A4B2",
  "userId": "abc123uid",
  "userEmail": "customer@example.com",
  "isGuest": false,
  "contactEmail": "customer@example.com",
  "status": "confirmed",
  "items": [
    { "productId": "xYz789", "title": "Red Floral Dress", "price": 1999, "qty": 1 }
  ],
  "total": 1999,
  "shippingAddress": {
    "firstName": "Priya",
    "lastName": "Sharma",
    "company": "",
    "address": "12 MG Road",
    "apartment": "",
    "city": "Bengaluru",
    "state": "Karnataka",
    "pinCode": "560001",
    "phone": "9876543210"
  },
  "billingAddress": { "...same as shippingAddress..." },
  "billingAndShippingAddressSame": true,
  "paymentId": "pay_OxyzRazorpay",
  "razorpayOrderId": "order_OabcRazorpay",
  "paidAt": "2026-03-21T10:05:00Z",
  "createdAt": "2026-03-21T10:04:50Z"
}
```

**Security rules:**
- `create` — anyone (guests + logged-in users). Cloud Functions admin SDK bypasses this.
- `read` — only the owner (`userId == request.auth.uid`) or admin
- `update` — admin only (status changes)
- `delete` — never allowed

**Composite indexes:**
- `userId ASC + createdAt DESC` — used by `apiGetMyOrders`
- `status ASC + createdAt DESC` — used by `apiGetAllOrders?status=`

## 3. `payments/{paymentId}`

**Document ID:** The Razorpay `payment_id` (e.g. `pay_8e3zew…`) or a mock ID in test mode.  
This collection acts as a **payment ledger** — one document per transaction attempt.  
⚠️ **PCI-DSS**: Full card numbers and CVV are **never** stored here. Only the last-4 and card network (from Razorpay's response) is kept.

| Field | Type | Required | Notes |
|---|---|---|---|
| `paymentId` | `string` | ✅ | Mirrors the document ID (Razorpay `payment_id`) |
| `orderId` | `string` | ✅ | Your internal `ORD-…` order ID — foreign key to `orders/` |
| `razorpayOrderId` | `string \| null` | | Razorpay `order_id` used for HMAC verification |
| `razorpaySignature` | `string \| null` | | HMAC-SHA256 signature returned by Razorpay — stored for audit trail |
| `transactionRef` | `string \| null` | | Internal transaction reference (e.g. `TXN…`) |
| `utr` | `string \| null` | | Bank UTR number for IMPS/NEFT/RTGS transfers |
| `amount` | `number` | ✅ | Amount paid in INR |
| `currency` | `string` | ✅ | Always `"INR"` |
| `status` | `PaymentStatus` | ✅ | See enum below |
| `method` | `string \| null` | | `"card"`, `"upi"`, `"netbanking"`, `"wallet"`, `"mock"` |
| `cardLast4` | `string \| null` | | Last 4 digits of card — **never full PAN** |
| `cardNetwork` | `string \| null` | | `"Visa"`, `"Mastercard"`, `"RuPay"`, etc. |
| `customerName` | `string \| null` | | From checkout form |
| `customerEmail` | `string \| null` | | From checkout form |
| `userId` | `string \| null` | | Firebase UID or `guest_…` |
| `isTest` | `boolean` | ✅ | `true` in mock/dev mode so you can filter test records |
| `capturedAt` | `Timestamp` | ✅ | Server timestamp when payment was confirmed |

### `status` enum

| Value | Meaning |
|---|---|
| `success` | Payment captured and verified |
| `failed` | Card declined / bank error |
| `refunded` | Full refund issued |

**Example document (real Razorpay):**
```json
{
  "paymentId": "pay_8e3zewSzXUoxkn",
  "orderId": "ORD-mn4bjjef-P4SXNI",
  "razorpayOrderId": "order_ZctwHs1HduwOB0",
  "razorpaySignature": "8189c032c4c65a2226e2…",
  "transactionRef": "TXNEBC16aAjfA",
  "utr": "GXZ8MGKBUNZL",
  "amount": 5059.96,
  "currency": "INR",
  "status": "success",
  "method": "card",
  "cardLast4": "4242",
  "cardNetwork": "Visa",
  "customerName": "Ashokkumar Sethuraman",
  "customerEmail": "ashokbca7@gmail.com",
  "userId": "abc123uid",
  "isTest": false,
  "capturedAt": "2026-03-24T10:05:00Z"
}
```

**Security rules:**
- `create` — Cloud Functions admin SDK only (clients never write directly)
- `read` — owner (`userId == request.auth.uid`) or admin
- `update, delete` — admin only

**Composite index:**
- `orderId ASC + capturedAt DESC` — for looking up payment by order
- `userId ASC + capturedAt DESC` — for customer payment history

## 4. `users/{uid}`

**Document ID:** Firebase Auth UID (same as `auth.uid`).  
This collection is written to by `apiUpdateProfile` and `apiSetAdminClaim`.  
Firebase Auth holds the primary profile (email, displayName, photoURL); this doc stores **extended / overridden** fields.

| Field | Type | Required | Notes |
|---|---|---|---|
| `displayName` | `string` | | Override for Firebase Auth displayName |
| `phone` | `string` | | Stored here because Auth phone requires OTP |
| `photoURL` | `string` | | Override for Firebase Auth photoURL |
| `updatedAt` | `Timestamp` | ✅ | Set on every `apiUpdateProfile` call |

**Example document:**
```json
{
  "displayName": "Ashok Kumar",
  "phone": "+919876543210",
  "photoURL": "https://example.com/avatar.jpg",
  "updatedAt": "2026-03-21T09:00:00Z"
}
```

**Security rules:**
- `read, write` — user can only access their own doc (`auth.uid == uid`)
- `read` — admin can read any user doc

## How to Create Collections in Firebase Console

Firestore is **schemaless** — you don't pre-create collections. They are created automatically when the first document is written. To bootstrap:

1. **Products** — Go to Firebase Console → Firestore → **Start collection** → Collection ID: `products` → Add a test document manually or deploy and call `apiAddProduct`.

2. **Orders** — Created automatically when a user checks out. No manual setup needed.

3. **Users** — Created automatically when a logged-in user calls `apiUpdateProfile`. No manual setup needed.

## Indexes to Deploy

Run this once after deploying to create the composite indexes:

```bash
firebase deploy --only firestore:indexes
```

Or deploy everything at once:

```bash
firebase deploy --only firestore
```

This reads `firestore.indexes.json` and `firestore.rules` and applies them to your project.
